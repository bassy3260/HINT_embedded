# 흐름 한줄 정리

## 다운로드
- 청크 단위로 받아 따로 저장, 끊겨도 이어받기
- 서버는 원본 파일만, 청크로 나누는 건 기기가 Range 요청으로
- 응답 구간(Content-Range)이 요청과 같은지 확인

## 서버 방해 (견고성)
- 실패한 청크만 자동 재시도 (최대 5번, 1·2·4·8초 대기)
- 10초 동안 아무것도 안 오면 포기 (멈춘 서버)
- 청크 하나 전체 30초 넘으면 포기 (질질 끄는 서버)

## 해시
- 청크마다 해시 확인 후 저장, 이어받을 때 저장본도 다시 확인
- 다 합친 뒤 전체 해시 확인 후 설치

## manifest
- 해시 목록을 담은 manifest 에 제작자 서명
- hw 넣어서 다른 하드웨어용 펌웨어 거부
- version 넣어서 옛 버전 거부 (다운그레이드 방지)
- 서명 시각·만료 넣어서 오래된 manifest 거부
- 크기·청크 수가 앞뒤 맞는지 확인

## 인증서 / CA
- 기기는 Root CA 하나만 믿고, 제작자 인증서는 CA 도장으로 확인
- 제작자 키를 바꿔도 기기 회수 불필요 (CA 가 새 인증서 발급)
- 인증서에 키 버전 → 유출된 옛 키 거부
- 인증서 용도는 펌웨어 서명 전용, 이름까지 정확히 확인
- 인증서 유효기간 확인

## 펌웨어
- 펌웨어 암호화 (서버엔 암호문만, 키는 개발자 PC와 기기에만)
- 복호화 후 평문 해시 확인

## 기기 기록 (뒤로 못 가게)
- 설치된 버전, 본 적 있는 최신 키 버전, 본 적 있는 최근 서명 시각 기억
- 기기 시각 = max(기기 시계, 기억한 시각) → 시계 되돌리기 방지
- 부팅에 실패한 버전 기억 → 다시 안 받음

## 설치 / 부팅
- A/B 칸 : 안 쓰는 칸에 설치, 끝나면 부팅 칸 표시만 한 번에 교체 (전원 차단 대비)
- 새 펌웨어는 시험 부팅, 확인 도장 없으면 이전 칸으로 롤백
- 부팅할 때마다 서명부터 다시 확인 (보안 부팅)

## 남은 것 (하드웨어 영역)
- 신뢰 기준(CA, 암호화 키, 버전·시각 기록)이 보통 파일 → 실제는 ROM·eFuse·보안 칩
- 중간 CA 없음
